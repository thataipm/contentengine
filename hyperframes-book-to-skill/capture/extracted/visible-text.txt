book-to-skill (github.com/virgiliojr94/book-to-skill)

Turns any technical book PDF/EPUB/DOCX/HTML/Markdown/RTF/MOBI into a structured Claude Code
skill instead of dumping the whole book into an agent's context window.

Real facts, verified live 2026-08-13 via the GitHub API and the README fetched directly:
- 20,978 GitHub stars, 2,212 forks
- Created 2026-05-01, last pushed 2026-08-12 (actively maintained, updated yesterday)
- MIT license
- Install: npx skills add virgiliojr94/book-to-skill
- Works with Claude Code, GitHub Copilot CLI, and Amp

How it works (verbatim from the README):
- Two-stage approach: an Extraction Phase (a deterministic Python extractor processes
  documents into clean text and metadata, entirely on the user's machine) and a Generation
  Phase (a spec-driven generator creates structured skill files following the open Agent
  Skills standard, with on-demand chapter loading to keep active context minimal).
- Real measured claim: "24x-51x fewer tokens than dumping the book into context" to answer
  questions, measured on real books.
- The generated skill's real size breakdown: core SKILL.md (~4,000 tokens, always loaded),
  per-chapter files (~1,000 tokens each, loaded on-demand), glossary (~1,500 tokens), patterns
  (~2,000 tokens), cheatsheet (~1,000 tokens).

Why this matters for this channel: this channel's own production pipeline hit the exact same
problem building its first HyperFrames episode (documented in ../hyperframes/CLAUDE.md's
"Orchestration discipline" section) -- dumping too much into an agent's context costs real
tokens and real time. book-to-skill solves the same class of problem for books that this
channel had to solve by hand for its own video production.

The one real gap worth being honest about: this is a spotlight, not an unqualified endorsement
piece -- only claims directly verifiable from the README/GitHub API are used, no invented
capabilities.
